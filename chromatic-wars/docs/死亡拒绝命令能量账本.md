# 死亡队伍的过期输出与能量账本

GPU 核心死亡后，CPU 通过低频异步团队快照收到淘汰通知。在通知返回之前，左侧真实弹球可能已完成输出：原弹药能量已经从该球移除，正常重生为 2，输出被放入 GPU 命令队列。

到期后的普通护盾、大球、狙击、风暴和机枪命令仍然不得为死亡队伍生产武器。拒绝分支将输入的完整 64 位整数能量计入 `consumed_energy`，作为**显式损耗**。这不产生攻击，也不改变死亡不生产的规则。否则该输入会从场内、库存、队列和累计损耗中同时消失。

每条命令只有执行成功时收费一次，并由原命令路径清除 `a.x`。护盾/机枪优先槽与普通命令环互斥，后续清槽和空刷新不会再次收费。未来命令尚未到期时不收费；仍可正常执行的死亡余波大球（带 `death` 标记的 `op2`）不经过此拒绝出口。

`tests/contact_energy_suite.gd` 提供 `-- --death-only true` 专项模式，覆盖五种命令共 83 能量、后续刷新去重、29 能量死亡余波以及定时 31 能量命令。也可以与 `--atomic-only true` 同时运行。测试结果以实际日志为准，新增夹具的存在不代表已经通过运行验证。

本轮已实际运行组合模式：`--atomic-only true --death-only true`，结果 **7 PASS / 0 FAIL / 0 NOT TESTED**，Godot 实际退出码 0，日志未见引擎错误。包含初始化、并行原子消费及上述五项死亡计账断言。原始日志为 `artifacts/validation-1.5/contacts-atomic-death-final.log`，逐项结构化结果为同名 `.results.json`。测试后等待异步回读排空并退出，无遗留 Godot 进程。

该运行使用 llvmpipe（LLVM 19.1.7）软件 Vulkan；这些正确性结果不代表 RTX 5060 Ti 的实际性能。

`--include-atomic true` 会保留默认接触/死亡总账回归，再附加并发原子消费测试；适合验证后续等价优化。它与仅执行指定专项的 `--atomic-only true` 不同，结果仍须以对应实际运行日志为准。

后续三处等价快路径优化完成后，已运行 `--include-atomic true`：默认接触/死亡回归26项加并发原子1项，共 **27 PASS / 0 FAIL / 0 NOT TESTED**，实际退出码0，引擎错误及警告均为0。对应 `artifacts/validation-1.5/contacts-nop-regression-final.log` 与 `.results.json`；Shader SHA-256 为 `b879f4b992c76e4f324a68b3ff076348f0c24f6d512e5b112b0bd4533f9e5356`。这是对同批机制的重复回归，不应与之前21项、7项日志相加宣称独立功能数。


后续严格目标锁定使用物理ID与出生代数识别目标：`Particle.aux.x` 低4位仍保留盾接触，高28位为每槽代数，死亡/清场保留代数，重生加1；`WeaponState.gun.w` 保存锁定代数。同槽新生实体不能继承旧目标CD身份。每槽代数到268,435,455后回1前，仅在串行出生的这个罕见分支清除四队对该槽的旧锁，避免代数回绕误认目标；世界重开同时重置粒子及武器目标。该改动不改变本节的死亡拒绝消费规则，但新的Shader必须另跑最终回归，不能沿用本节此前b879阶段的PASS冒充新构建结果。
