# GPU状态、布局和同步

右侧唯一权威状态属于主 `RenderingServer.get_rendering_device()`。CPU的 `stats` 仅供显示与保命握手，不能写回覆盖GPU团队或粒子。资源创建、上传、dispatch、异步读回和释放均排入渲染线程；不创建本地设备，不调用本地设备 `submit()/sync()`。

## std430 与 binding

| binding | 资源 | 布局 |
| --- | --- | --- |
| 0 | 粒子与大球 | `(capacity + 64) × 64B`；普通/狙击共用前部容量，大球在尾部 |
| 1 | 阵营 | 4×128B |
| 2 | 领土 | 每格uint，0/1/2/3为阵营，其他为中立 |
| 3 / 4 | 空间桶头 / next链表 | 128²×4个桶头；完整节点链，无长度截断；next尾部64槽保存大球航向 |
| 5 | 命令 | 每条32B；1024持久环、4保命槽、8盾/枪优先槽 |
| 6 | 统计及大球粗索引 | 64×uint；`stat[32..63]`为4×4格、每格两uint的大球位图 |
| 7 | 输出图像 | RGBA8，STORAGE + SAMPLING，Texture2DRD直接采样 |
| 8 | 粒子像素暂存 | GPU原子合成，不回CPU |
| 9 | 参数 | 64个float槽，共256B；部分槽按uint原位编码整数 |
| 10 | 武器状态 | 每队128B，共512B |
| 11 | 活跃池 | 16个uint头部 + capacity个活跃ID + capacity个空闲ID |
| 12 | 间接调度及诊断 | 32个uint，共128B，带 `STORAGE_BUFFER_USAGE_DISPATCH_INDIRECT` |

粒子64B：0..15位置/速度；16..31能量low/high、队号、类型；32..47半径、小粒子出生速率或大球出生门槛、旧位置；48..63为按类型复用的接触/出生状态。类型0空、1普通、2狙击、3大球。普通aux.y可存子步内出生时长，aux.z最高位为出生标记，aux.w为高速分类；狙击aux.y低位为等级，aux.z bit30为待分裂；大球aux.y/aux.w为64槽接触掩码。

阵营128B：0..15盾与枪u64；16..31风暴与狙击储备u64；32..43生命状态/请求nonce/死亡nonce；44..47奇数ID威胁摘要；48..63模拟时钟、射击相位及枪角；64..67偶数ID威胁摘要，68..79兼容计数字段；80..95核心位置/核心半径/盾半径；96..127其他握手及瞄准视觉状态。状态0存活、1待保命、2死亡。威胁摘要不是弹药或累计射击数，当前风暴事件状态属于binding10。

武器128B：0..15机枪单发整数能量/目标ID；16..31目标切换就绪时间及补领土缓存/游标；32..47风暴总发数/下一发/圈数/当前圈；48..63风暴整数商与余数；64..79下圈时刻/相位/上一圈完成时刻；80..95固定盾参考与扩张目标；96..111扩张游标；112..127完成风暴/圈/狙击分裂的诊断计数。

池头 `pool[0..2]`为活跃数、普通空闲数、狙击空闲数，`pool[3]`为累计回收数。活跃表从word16开始，空闲表从word `16 + capacity`开始；最后8个物理槽为狙击预留。只在串行发射/回收阶段改表；能量归零先标类型0，事件后稳定压紧并回收一次，物理ID不移动。

binding12的word0..2、3..5分别是普通、普通加64大球的dispatch参数；word8/9是可选候选/接触累计数，10..12为池计数，16..19为四队活跃实体数（含普通、狙击、大球，死队余波仍计入）。详见[GPU活跃粒子索引](GPU活跃粒子索引.md)。

## pass依赖与物理写入

每子步：命令/发射 → mode11刷新间接参数 → 并行运动 → 清桶与威胁摘要 → 原子建完整链 → 九色邻域碰撞 → 串行实体/领土事件与狙击分裂 → mode12压紧回收并刷新间接参数。模式2、4、9用GPU间接参数，其余粒子事件与统计按活跃ID访问。批末清像素 → 粒子/大球覆盖 → 地图、核心、盾与最终输出。

每次dispatch有compute barrier。Godot4.6的 `compute_list_add_barrier`结束并恢复列表；间接调度登记参数缓冲为 `RESOURCE_USAGE_INDIRECT_BUFFER_READ`，依赖图保证SSBO写入对后续间接读取可见。CPU不读取当步活跃数来算groups，不使用上一批遥测作为当步发射/调度依据。

格宽8游戏单位，子步满足两倍位移加两半径不超过8。九色中心格按 `(x % 3) + 3 × (y % 3)`分组，同色3×3链表写集合互不重叠，跨色屏障隔开写入。配对按唯一ID去重，密集链完整遍历；超安全位移的高速链在串行事件中对实际活跃ID完整补查，不截断候选。

建桶时atomicMin汇总偶/奇ID威胁候选，包含高速粒子。键为12位反向评分加20位ID，覆盖100万容量，只用于索敌。下一子步重新检查候选，目标切换CD为武器状态的模拟时钟，炮口持续转向。`par[12].w`是默认开启的己方普通碰撞开关，也约束高速回退，不改变己方补大球。

大球存活掩码按ID升序，4×4粗索引覆盖扫掠范围。普通事件按当次活跃ID顺序串行处理；狙击逐段找最早实体接触并先结算领土；新分裂子弹下一子步才移动。空槽重用会改变活跃顺序，不承诺跨容量或倍速逐位相同轨迹。

mode7只在初始化、低频遥测或显式Debug需要时统计活跃ID及64个大球槽，未变更时复用。领土面积由初始化、真实归属变更及显式debug维护，不周期扫描整图。物理不依赖遥测计数；胜负观察还要考虑死亡队伍的余波。

普通首次染非己方格消耗全部剩余能量；狙击/大球每格扣当前普通成本；盾扩张每格扣1护盾能量。uvec2整数累计上限2^63−1，CPU正式左侧输入精确上限2^53−1。浮点只作运动和几何映射，UI万/亿格式不是权威输入。详见[GPU架构与精度](GPU架构与精度.md)和[武器整数结算与默认分裂](武器整数结算与默认分裂.md)。

物理长度用游戏单位，右侧边长1024，输出像素数与领土格数独立。速度/加速度、发射间隔、目标切换和玩法CD用模拟秒；遥测、界面刷新和提示显示用真实时间，不参与账本。

## 命令、保命与读回

正式左侧输出携带发生模拟时刻。晚于合并批次末步的命令留在CPU，已上传命令由GPU逐步检查时间，不能批首全部提前生效。命令和GPU时刻统一float32域，避免CPU double比较错过批末。调试、保命回复和明确死亡余波保持立即语义。

同队盾/枪每类每flush只上传首条补给，重复补给及满环/满槽命令继续保存。环按连续完成前缀回收，可先执行后方就绪命令；排队不保证倍速间严格相同的生效时间。

核心致命接触在CD就绪时进入待定并递增nonce，CD中则淘汰。CPU只抽最大左球并回传nonce/能量，GPU统一决定补盾或死亡。接触保护避免同次攻击重复扣新盾或刚破盾即杀核心。死亡队伍仍可有真实余波，不能仅凭“剩一队核心”忽略它们。

正式每约0.25真实秒读取四队512B、统计256B、大球4096B、诊断128B，共4992B。Godot4.4+异步，兼容分支低频同步。`cpu_submit_ms`是CPU排命令时间，`explicit_cpu_gpu_sync_wait_ms`只记同步读回阻塞，`async_readback_latency_ms`含排队和调度；不能混用。模块申请字节数不是驱动完整VRAM用量。

`gpu_profiling`默认关闭，开启才额外记录候选/接触。累计uint32短窗差值用 `(end - begin) & 0xffffffff`处理回卷；GPU timestamp纳秒除1,000,000得毫秒。阶段工具可能拆compute list，须注明调度开销区别。

Debug的 `sample`读取固定前64物理槽、最后8狙击槽、64大球、武器、池头及少量指定领土；前64槽不是“前64个活跃粒子”。合并粒子和狙击数组须按真实ID去重。小容量规则套件可显式 `all_particles`读全表检验回收后高ID；正式遥测和大容量性能矩阵不得改为全表读回。截图是显式工具操作，不参与正式渲染。

## 异步资源生命周期

每个读回登记 `pending_readbacks`。无论成功、长度不足或已成为旧代，回调均归还登记；API失败/长度错误明确报告，不能解码空表并称为通过。旧代回调不发新代通知、不读新代时间戳。

`shutdown()`停止工作、增代并断开纹理；已登记回调全部归还后，才在渲染线程释放uniform/pipeline及底层资源。`resource_release_confirmed`表明释放已执行；`is_shutdown_complete()`要求关闭状态、释放确认及读回数0同时成立。主场景退役和退出流程等待该条件后销毁节点/退出，不依赖“等若干帧”。

同对象有读回或未完成释放时，`start()`拒绝重用；正式重开新建对象并退役旧对象。测试也须先shutdown、等释放确认、再queue_free。驱动卡死或回调无法归还仍可能阻止完成，测试超时必须明确失败，不能强行释放后记为通过。
