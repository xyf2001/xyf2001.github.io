# GPU状态、布局和同步

右侧唯一权威状态属于主 `RenderingServer.get_rendering_device()`。禁止将新的CPU团队副本写回覆盖它。CPU的 `stats` 只用于显示和请求握手。所有RD创建、更新、dispatch、异步读回和释放都排入渲染线程；不创建独立设备、不调用本地设备submit/sync。

## std430 与 binding

| binding | 资源 | 布局 |
| --- | --- | --- |
| 0 | 粒子与大球SSBO | `(capacity + 64) * 64B`；普通粒子在前，大球在后 |
| 1 | 4个阵营SSBO | 每队128B |
| 2 | 领土SSBO | 每格uint，0/1/2/3为阵营，4为中立 |
| 3 / 4 | 空间桶头 / next链表 | 普通粒子每节点完整链，不截取前32个；next尾部64槽保存大球最近有效航向 |
| 5 | 命令SSBO | 每命令32B，普通持久环、保命优先区和充能优先区 |
| 6 | 统计SSBO | 64个uint，共256B |
| 7 | 输出storage image | RGBA8，STORAGE + SAMPLING，Texture2DRD直接采样 |
| 8 | 粒子像素暂存 | GPU原子合成，不回CPU |
| 9 | 参数SSBO | 64个float，共256B |

粒子64B：0..15位置速度vec4；16..31能量low/high、队号、类型uvec4；32..47半径、出生速率（小粒子）/出生体积门槛（大球）、前一位置vec4；48..63接触保护和种子uvec4。类型0为空、1普通、2狙击、3大球。

阵营128B：0..15护盾与机枪u64；16..31风暴与狙击储备u64；32..43生命状态/请求nonce/死亡nonce，44..47奇数粒子ID威胁摘要；48..63CD就绪时间与机枪射击相位；64..67偶数粒子ID威胁摘要，68..79风暴环状态；80..95核心位置/核心半径/护盾半径；96..127其他状态。生命状态0存活、1待保命、2死亡。CPU读取必须使用这些偏移，不可把0当死亡。威胁摘要不表示弹药或累计发射数。

能量使用两个uint承载非负整数，支持的累计上限为2^63−1，实际染格与抵消使用整数加减；普通粒子首次染一格消耗剩余出生能量，狙击/大球每格扣当前粒子成本，不依赖大float逐格减法。CPU左球通过double传入，因此输入精确上限另外为2^53−1；超出时由左侧明确暂停。不要把UI格式化后的万/亿数字作为权威输入。

## pass依赖

每一步：优先握手/命令及GPU发射 → 并行运动 → 清空间桶 → 原子建完整链 → 九次不同颜色邻域碰撞 → 顺序GPU大球/盾核/领土事件。每个dispatch后都有compute barrier。绘制在批次末执行：清像素 → 原子粒子/大球覆盖 → 地图、核心、护盾与纹理输出。

1.4.3起，清空间桶时也将两组机枪威胁摘要重置为UINT_MAX；建桶时并行atomicMin选出偶/奇粒子ID各一个候选（含高速粒子）。键为12位反向评分加20位粒子ID，覆盖100万容量。下一子步prepare重新检查存活、阵营、距离及运动方向，不设置角度保持时间；已消耗候选忽略，之后重建。摘要只用于索敌，碰撞链仍完整，不截断物理候选。`par[12].w`为己方普通粒子碰撞开关，默认1，同时约束常规网格和高速回退，不改变己方粒子补大球能量。

所有物理长度使用游戏单位；右侧战场边长1024游戏单位，与渲染纹理的像素数、领土网格的格数独立。速度/加速度按模拟秒计算。参数、CD和玩法计时使用模拟时钟；低频遥测、界面刷新和提示消失使用真实时间，不参与游戏结算。

性能修复版只在初始化、低频统计读回或显式Debug快照前运行mode7的普通粒子/大球计数与64位能量统计。未发生新物理/命令修改且统计已最新时，Debug快照复用该GPU结果。领土四计数由初始化、正式claim归属变更和显式debug15/16同步维护，不再单线程扫描512²地图。领土计数、活跃计数均不参与正式物理决策。早期共享工作组统计方案在软件Vulkan中出现明显退化，未纳入最终版本。

发射分配在一次prepare中只占槽、不释放槽；首次扫满后缓存本次调用的满载状态，余下发射直接保留储备，下一GPU子步重新寻找。测试清空命令同时清该缓存。大球交互先用两个uint建立64槽的有序存活掩码，仅检查实际大球；没有大球时跳过普通粒子×大球循环。遍历仍按原ID升序，保持抵消、领土和盾核结算顺序。

空间格宽8，128²格头；子步限制满足两倍位移加两半径不超过8。九色碰撞的中心格按 `(x % 3) + 3 * (y % 3)` 分配，一个线程处理中心格与相邻八格；同色中心的写入邻域互不重叠。跨色屏障阻止并发写同一个粒子。配对按唯一索引排序，不重复抵消。密集桶遍历完整链，最大占用作为诊断。密度极高时局部配对成本仍会显著增加。

领土、护盾和大球共用单GPU事件处理者，按固定实体索引顺序结算，消除了线程调度导致的额外染色或丢扣；代价是吞吐瓶颈。普通粒子使用格子DDA，大球使用扫掠胶囊覆盖网格中心，普通粒子首次真实归属变更后消失，狙击/大球每个真实归属变更扣当前粒子成本。不能用随机领土动画替代。

## 保命与读回

左侧正式落槽命令携带发生时的模拟时刻。CPU每帧可合并最多8个固定步；超过本批末步的命令继续留在CPU队列，已经上传的批内命令则由GPU逐步检查时间后执行，不能全部在批首提前充能或出生。命令与固定步时刻统一到float32域，避免长局时CPU double与GPU float量化不同而错过批末事件。调试发射、保命回复和明确标记的死亡余波保持立即命令语义。

盾/枪优先区每队每类每次flush只上传首条；同批重复补给继续保留CPU，后续flush再发，可能延后生效。大球槽满或命令环满同样保留待发能量；不能把上述排队行为当作严格的每档倍速轨迹一致性保证。

无盾核心的致命接触先进入待定并递增请求nonce；CD期间则GPU确认淘汰。待定状态不允许CPU尚未回复时先死。CPU读取请求后抽最大球，回传nonce和能量；GPU去重并统一补盾或淘汰。请求所对应攻击有接触保护，不能补盾后同一次接触继续致死。

正常每0.25真实秒读取4队512B、统计256B和64颗大球4096B，合计4864B。Godot4.4+异步，4.3兼容分支低频同步。普通粒子表、领土整图和输出纹理均不在正式读回路径。64颗大球的小遥测只供数字跟随；物理仍在显存。

独立测试允许读取前64颗粒子与少量指定格子。视口截图是显式工具操作，与正式渲染无关。不得把调试快照改成每帧整场更新。
