# GPU 架构与精度

右侧正式路径使用 `RenderingServer.get_rendering_device()` 的主 RenderingDevice，在渲染线程创建、运行、释放资源。`Texture2DRD` 共享 RGBA8 输出纹理给 Godot 画布。没有本地 RD，没有 `submit()/sync()`，没有整帧 GPU→CPU→GPU 绘制，也没有 CPU 遍历普通战场粒子。

## 模块及缓冲布局

`GPUWorld` 管生命周期、固定步批处理、参数和少量异步统计；`GPUEmitters` 编码真实左侧输出；`GPUCollisions` 限制最大子步；`GPURender` 创建共享输出。全部模拟内核在 `shaders/battle.glsl`，按明确的模式分派。

## 每步依赖及竞态处理

每个固定步依次执行：优先命令/持久命令/有预算的发射 → 移动及墙反射 → 清网格 → 建空间链表 → 9色邻格碰撞 → GPU串行实体/领土事件。每次分派后插入 compute barrier；9个颜色phase之间也各有屏障。全部固定步完成后清粒子像素、粒子绘制和最终合成，渲染线程只接收一次整帧批处理。普通粒子总数和64位能量只在初始化、低频读回或显式Debug快照前统计，结果最新时复用；四队领土面积随唯一的归属变更出口精确增减，不再周期扫描整图。

每个颜色phase只允许间隔3格的中心格工作，各自3×3静态链表集合互不重叠。中心格按phase直接紧凑映射，每相位最多43²候选，避免调度整张128²网格后丢弃8/9线程。每个中心格由一个GPU invocation处理；索引较小者负责一个粒子对，所以不会双扣能量、两个线程写同一粒子，也不会只处理每格前32颗。不同半径的大球不进入普通空间链表，使用独立64槽的GPU串行实体处理。

普通粒子跨格采用 Amanatides/Woo DDA，逐个经过的格子处理；改变一个非己方格子严格扣1能量。串行事件给领土争抢确定顺序。大球按扫掠胶囊覆盖格子中心定义占领，每格严格扣1；这是一种明确的栅格化定义。

按设定的最大粒子/狙击/大球速度动态细分，单体每子步位移不超过`min(4, (8 - 2 * 普通半径) / 2)`像素，且dt不大于1/120。这使两倍位移加两半径不超过格宽8，仍可使用3×3邻格；默认半径1.2/速度620每1/120固定步仍为两个GPU子步。更大半径或更高速度需要更多子步。实体接触采用扫掠检测；先找最早盾/核心接触，领土先消耗该接触之前路径，再处理实体，不能隔着敌地直接伤盾。极端密集、多次弹性反冲把瞬时速度提升到明显超过设定速度的场景仍需目标硬件及长局验证。

盾接触立即分离、反射且带接触去重。一次接触刚好破盾仍立刻结束，不能同事件继续检测核心。致死时GPU先检查模拟时间CD：冷却中直接确认死亡；就绪则冻结为等待保命，递增nonce。CPU只抽该阵营最大左球并返回能量及nonce，GPU决定补盾或死亡。旧nonce结果无效。同一攻击带事件保护，补盾后先推出盾圈，不会用滞留接触再扣新盾。等待期间其他正常充盾已生效时，失败救援也不能杀死仍有盾的核心。

死亡在GPU把全部机枪余量移入风暴；CPU只把真实左侧剩余球各提交一次大球，死队余波允许发射。队列不会因为已死亡而误拦截余波。

## 精确模式、打包模式及数值边界

默认精确模式每普通/狙击粒子1能量。打包模式允许一颗可视对象携带多点能量：每格仍只扣1，异队相撞等量抵消，剩余能量继续运动。能量包改变碰撞几何和动量分布，不能与逐粒子模式宣称逐点相同。UI显示模式、每包目标能量、当前活跃能量包比例和待发能量。普通能量包超过护盾时，护盾只抵消可用能量，包剩余部分反射；精确单能量普通粒子被盾吸收。

能量以两个uint实现整数加减和比较，受支持累计上限为 **2^63−1**，避免Godot UI有符号整数溢出。CPU输出接口是float，单笔精确整数范围为 **0到2^53−1**；左侧达到明确上限停止继续放大并显示诊断。数值只在半径/质量映射和UI紧凑显示时转float。超出GPU累计范围会保留待发命令、置错误位，中文诊断停止模拟，不能静默绕回或丢弃。

粒子容量满、64颗大球槽满、某队上一笔狙击尚未发完时，待发能量保留在库存或队列。持久环可先执行后面的就绪命令，独立盾/枪优先槽避免技能长积压阻塞即时充能。环仍使用连续前缀回收；持久技能长期积压会限制后续技能上传，UI显示实际命令积压和环占用，CPU继续保存其能量。

一次prepare首次找不到空槽后，本invocation缓存该池已满，避免每队每武器反复扫描全部容量；下一子步自动清缓存。大球交互只遍历两个uint掩码标记的实际大球，保持ID升序；无大球时不执行普通粒子×64空槽扫描。

## 性能及验证边界

当前优先正确性。领土/盾/核心竞争由单GPU invocation顺序处理；大球交互是O(N×B+B²)，B≤64。普通空间格的局部高密度仍可出现O(k²)；这不同于对全部粒子无条件O(N²)，但热点性能代价真实存在。高粒子容量不是60 FPS承诺，30万/100万尤其需要真实独显测量。软件Vulkan的性能不能代表Windows独显。

正式统计每约0.25真实秒读取256字节统计、512字节阵营和4096字节大球表（约4.75KiB），用于UI及保命握手；等待保命提供GPU事件保护，不会先死后救。Godot4.4+异步；4.3缺少该异步API，只对这些小表低频同步读取。`debug_readback`额外读取前64粒子和最多1024领土格，仅独立自动测试使用，绝不参与正式绘制。

GPU时间取主RD Vulkan timestamp差，单位纳秒转毫秒。Godot4.6 XML说明写微秒，但其Vulkan驱动`timestamp_query_result_to_time`实际返回纳秒；此处按实际源码换算。UI的GPU时间覆盖当次所有固定子步及输出合成。

开发目录动态编译当前GLSL原文并报告第一条真实编译错误；导出PCK若不含原文则加载Godot标准RDShaderFile的SPIR-V。Windows导出前须用Godot完整导入项目。资源创建/绑定失败显示中文错误，不切换CPU战场。
