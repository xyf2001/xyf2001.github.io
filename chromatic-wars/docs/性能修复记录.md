# 性能修复记录

记录日期：2026年10月16日（北京时间）。最终发布版本：`1.1.0-perf1`。本次记录由已交付初版、被撤回的中间方案和已完成GPU36项与真实风暴短采样的最终性能修复方案组成。每份日志只证明对应代码版本、输入和时长，不把旧测试迁移成新版PASS。

## 用户现象与诊断范围

用户反馈RTX 5060 Ti在0.25×速度、真实风暴发射后约2 FPS。此项是用户现场反馈；云机没有该显卡，无法替用户确认新版Windows帧率。独显无法自动消除GPU单invocation内的大量串行循环，选择了Vulkan也不等于所有工作已充分并行。

初版下载对应提交`330d8788cd959786dd50e2acbc7448a2ef5f18bb`。云端实测环境为Godot4.6.3、Debian13、5 vCPU、Mesa25.0.7的llvmpipe软件Vulkan。以下时间只能比较这些明确夹具，不能外推RTX帧率或承诺Windows60 FPS。

本轮没有通过降低默认粒子容量、把默认精确模式换成能量包或降低目标速度来解释为优化。实际设备名称加入战场诊断及顶栏悬浮提示；侧栏“复制”按钮复制包含版本`1.1.0-perf1`的JSON诊断并写入`CHROMATIC_DIAGNOSTICS`日志，包含设备、FPS、GPU时间、容量、精度、速度、步长和积压。隐藏球详情面板不再无条件重建80个cell的BBCode表。

## 最终保留的改动

| 原有成本 | 本轮处理 | 保留的正确性边界 |
| --- | --- | --- |
| 16px空间格在密集风暴区域产生较多候选配对，9个phase各调度全格后再筛选 | 改为8px格、128²格头，9个phase直接调度其紧凑中心格；链表仍完整 | 不截断每格粒子数，不丢弃候选以换取速度；局部高密度仍可能O(k²) |
| 缩小网格后若仍允许4px位移，步末邻格候选可能漏掉高速相向接触 | 同时把子步位移限制为`min(4, (8 - 2r) / 2)`，并限制dt≤1/120 | 满足配置速度下`2×位移 + 2×半径 ≤ 格宽`；默认r=1.2、620速度仍为每固定步2子步；极端弹性反冲超配置速度仍需专项测试 |
| 普通池满时，每队每武器反复扫描全部容量找空槽 | 每次prepare第一次确认相应池满后缓存失败，后续同池申请快速返回；下一prepare重新检查 | 未发能量仍留原库存/命令；不会永久记满，也不会吞掉待发弹药 |
| 普通粒子逐个检查64个大球槽，即使不存在大球 | 两个uint组成64位活跃大球掩码，只遍历实际存在的ID，并保持原ID升序 | B个活跃大球时仍有O(N×B+B²)，B≤64；没有改成CPU物理或改变结算顺序 |
| 为遥测重复扫描512²领土地图 | 初始化直接建立四队面积；claim与显式调试染色15/16维护owner计数增减 | 只在格子归属真正改变时加减；中立地不计入四队；领土竞争仍在原串行GPU事件中处理 |
| 每个渲染batch都扫描普通粒子统计；小表快照又可能重算 | 单invocation的mode7只在低频统计/显式dirty快照前执行，完成后清dirty | 状态实际修改后才标dirty；快照读取新统计，未把过期数据冒充完成状态 |

右侧仍使用主RenderingDevice的SSBO和storage image，Texture2DRD直接显示。普通粒子和领土没有CPU逐粒子模拟或逐帧整图回读。CPU读取的常规数据仍是约4.75 KiB的团队/统计/大球小表。

## 被撤回的并行统计方案

第一轮曾尝试64线程共享归约与原子合并普通能量/四队面积。软件Vulkan的准确匹配batch测量出现真实退化，故最终撤回并行统计，改为上表的owner增量计数与低频dirty粒子统计。该中间方案的实际结果原样保留，不能挑选更早缓存计时中的正向数字代表最终版。

以下每项均为相同夹具的中位`墙时 / GPU批次`毫秒。前三项初始及最终总能量分别为64、10000、810000，最终快照与原版一致，溢出均0。有盾场景最后活跃9997与9998存在差别，但`active能量 + reserve + consumed`均为810000，盾值均为3999772；未要求并行原子链表排序导致的局部轨迹逐点一致。

| 相同场景 | 初版基线 | 被撤回的并行统计中间版 | 最终版该夹具 |
| --- | ---: | ---: | --- |
| 容量10000、活跃64 | 31.122 / 16.274 | 156.791 / 106.675 | 未重跑（NOT TESTED） |
| 活跃10000、无储备 | 61.622 / 39.479 | 133.164 / 62.936 | 未重跑（NOT TESTED） |
| 活跃10000、四队各风暴10万/狙击10万，池满无法发射 | 60.439 / 44.297 | 210.028 / 123.193 | 未重跑（NOT TESTED） |
| 上述满载场景、四队护盾各1M | 64.734 / 44.422 | 150.962 / 126.327 | 未重跑（NOT TESTED） |

原始准确证据：[初版基线](../artifacts/perf_before_matched.json)、[中间方案退化](../artifacts/perf_after_matched.json)及同名`.log`。每场景排除2个warmup，测10个batch；容量/领土/输出10000/512²/768²；每batch1个1/120秒固定步，默认武器速度下2个GPU子步；强制包含到期统计。等待GPU小表异步回调完成才结束墙时，batch用跨场景唯一标签匹配GPU纳秒时间戳。窗口FPS单列，不冒充模拟步吞吐。

这些夹具采用GPU调试命令生成实际粒子、全己地保持计量，属于吞吐fixture，不能代替真实武器风暴场景，也不能代表20分钟对局。软件设备与宿主调度存在明显时序波动；退化数据仍是本次实际观测结果。

### 时间戳测量修正历史

- `perf_*_legacy_cached_timestamp.*`：初次工具读取游戏界面缓存的上一批GPU时间，出现GPU151ms却对应墙时48ms的矛盾；相关GPU值不可用于逐批对照，墙时和能量记录仍是当次实际观测。
- `perf_*_per_scenario_id_legacy.*`：工具已增加独立batch标签，但ID仅在场景内唯一，跨场景可能命中旧标签；不作为最终对照。
- `perf_before_matched.*`与`perf_after_matched.*`：场景前缀与batch编号共同唯一，40/40正式样本均匹配，不复用游戏计时缓存；保留真实正负结果。
- 最终方案没有再运行上述均匀点阵匹配batch夹具，未生成`perf_final_matched.json`；最终性能证据改用下节明确标注的真实武器风暴短采样。不得直接将中间方案结果更名成最终结果。

## 最终代码的真实风暴剖析

原版与最终版都通过正式`output(team, storm, 100000)`发射四队风暴，保留默认1万容量、512²领土、768²画面、精确粒子模式。均经26个固定步实际达到10000活跃粒子，然后采样3次；每次推进1个1/120秒固定步，实际2个GPU子步，没有用均匀注入替代武器发射。

| 阶段中位数 | 初版 | 最终代码 |
| --- | ---: | ---: |
| 九色碰撞GPU时间 | 244.620 ms | 49.673 ms |
| 领土/护盾/大球事件GPU时间 | 34.904 ms | 6.397 ms |
| 统计GPU时间 | 6.276 ms | 0.739 ms |
| 发射准备GPU时间 | 4.634 ms | 1.020 ms |
| 画面计算GPU时间 | 16.618 ms | 21.051 ms |
| 墙时，含快照与时间戳等待 | 420.010 ms | 150.188 ms |

所有样本保持10000活跃粒子、8400000总能量守恒、溢出0。原版3次墙时402.256/505.206/420.010ms，最终版89.844/150.188/226.328ms；软件Vulkan存在明显波动，画面计算阶段中位数还高于原版。这些真实负向数据与正向数据同时保留。

**该诊断为取得各阶段时间戳，把采样dispatch拆为独立compute list，会改变调度成本；墙时还含小表与时间戳等待，且只有3次短样本。不能把表格倒数当成实际游戏FPS，不能由此推算RTX5060Ti帧率。** 原版16px格最大占用56、最终8px格17，格面积不同，仅作各自密度诊断，不用56/17宣称提速。

证据：[原版真实风暴](../artifacts/storm_profile_before.json)、[最终真实风暴](../artifacts/storm_profile_final.json)、[汇总及源文件哈希](../artifacts/storm_profile_final_summary.json)、[对照说明](../artifacts/storm_profile_final_summary.md)。
