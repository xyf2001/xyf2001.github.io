# 1.5.1 · 实现与验收范围

本轮允许并要求实际运行、规则回归、性能矩阵和长时间模拟。本文件更新到取消发射成本、统一每格1能量及机枪固定T库存计划的新规则；当前武器/GPU140项、接触与并行整数32项及设置47项已实际通过。具体已完成项目以 `TEST_REPORT.md` 和对应原始日志为准，1.5.0的通过结果不转记为1.5.1重跑证据。云端设备为 llvmpipe 软件 Vulkan，任何计时均不能作为 RTX 5060 Ti 实机数据。

## 保留的玩法与新的整数结算

- 所有正式战场状态仍常驻主 RenderingDevice，画面使用共享 Texture2DRD。CPU只处理左侧16球、UI、命令与少量遥测，不逐粒子模拟，也不逐帧读回地图或画面。
- 普通/聚能敌方粒子碰撞按双方64位整数能量的最小值等量抵消，剩余实体沿原方向继续。同阵营普通粒子真实碰撞且不扣能，现有开关保留。狙击与普通粒子不发生物理偏转。
- 彻底取消随时间增长的发射成本。普通粒子、风暴粒子、狙击和大球每次实际改变一个非己方格子的归属只扣1整数能量，己方格不扣；余能继续移动并可以连续染色。先前的碰撞抵消不重复扣除。护盾扩张同样每次实际变更一格扣护盾1能量。能量归零的实体立即退出物理系统，残影只承担视觉作用。
- 大球接触使用碰撞前的质量、速度和法向入射计算反弹与部分损耗。碰撞后不因质量下降重新放大冲量。基础移速由独立、有限加速度驱动补足，不将损耗能量转换为瞬时速度。
- 机枪默认固定1200个发射时间槽/模拟秒。最近一次真实补弹生效后，剩余库存与新输入组成总能量`E`，按锁定射频在固定`T`模拟秒内的计划槽数`N`分摊；`T`默认10、可调0.1～120模拟秒。初始库存采用同样计划。以纯整数商`q`和余数`r`均匀分配`E=N*q+r`，没有补弹时不重新定价；`E<N`时均匀稀疏发出正能量，空槽不创建零能实体。
- 补弹所在子步先完成旧计划到期发射，步末按实际余量加新输入建立新T窗口；连续射击相位、炮口、目标身份和CD均不重置。新的正射频或T参数在下一次真实补弹时锁入计划。射频0是人工停火，库存与原计划保留；满池背压和人工停火是超过名义T的明确例外，不丢能、不瞬时补发积压弹。初始在射频0下取得的库存等恢复正射频时再建计划。
- 机枪转向持续跟随，目标切换CD默认0.5模拟秒，期间有效原目标不会被高分新威胁提前抢占；目标死亡、己方、失效或槽位换代立即重选，不等待CD。旧存档中的显式合法CD保留。局部真实格滚动扫描补足离散射线，避免长期漏掉单格敌地。
- 每次风暴最多1080颗、最多3圈。正输入能量`E>=360`时，取不超过`min(E,1080)`的360整倍数，每圈360颗；只有输入不足360时使用一圈`E`颗1能量的稀疏粒子。事件总能量用整数商余分配，世界进程不改变这一分配。容量不足时保留事件进度与库存，实际圈间延迟可因背压而延长。
- 狙击三级分裂暂保留当前稿：初始第1级，真实墙/敌盾/敌大球接触后，把碰后剩余能量分为父弹与子弹，子弹为30%向下取整、父弹取得其余及整数余数；双方进入下一等级，第3级不再分裂。默认相对真实反射方向左右各8度，可调。普通粒子抵消和领土不触发分裂，无空槽时保留待分裂状态与完整能量。历史1.4.3没有该比例，70%/30%的最终分配对象仍待用户确认，不作为语义验收通过；来源详见[狙击比例来源与待确认](狙击比例来源与待确认.md)。
- 护盾缩放参考基准与世界时间解耦；能量不变时不会因世界成长缩小。充能触发从核心向外的同心环扫描；真实扣能或用户修改半径参数仍可改变护盾大小。

## 左侧成长与防卡

每球正常出生仍为2，锁定当时体积门槛。令默认T0=100、目标T*=1,000,000、D=1200模拟秒、τ=1200模拟秒：

`T(t) = T0 * exp(log(T*/T0) * (sqrt(1+t/τ)-1) / (sqrt(1+D/τ)-1))`

该曲线准确通过开局和20分钟目标，连续增长且相对增长率递减。CPU/GPU采用同一公式，单球倍率或保值防卡不刷新出生门槛。浮点映射设有明确的1e30数学安全帽；左侧弹药精确整数上限仍为2^53−1，超过时暂停并保留原值，不能宣称无限期数值增长。

空气墙按真实半径、质量、速度产生连续力与下冲阻力，不按当前全局门槛禁止输出。倍率实体净宽、完整圆进入判定和底墙防逆入保留。修正默认下层柱壁净距不足最大球直径的问题，保留15根可编辑预设柱和用户自定义柱原坐标。静止防卡3模拟秒、局部循环8模拟秒、确认0.4模拟秒；增加当前速度检查，避免确认期末已经恢复运动仍误重发。重发保值并保留出生基准，不算倍率或武器输出。自然防卡频率和热点必须如实记录，不能仅因套件通过就宣称完全无卡球。

## GPU容量与同步

- 新增GPU常驻活跃ID表、普通空闲栈和8个狙击预留槽。物理ID稳定，结束事件后只压紧ID表与回收死亡槽，不搬动粒子实体。
- 移动、建桶、绘制采用GPU生成的间接dispatch，事件与统计只遍历活跃ID，避免大容量空池每子步全扫。正常路径不为读取活跃数量增加CPU/GPU同步。
- binding10：每队160B武器状态，共640B，新增机枪整数槽数/序号/余数/累加器与计划时间、锁定射频和T；binding11：16字头+容量个活跃ID+容量个空闲ID；binding12：间接调度参数和可选诊断，共128B。原有Particle64B和Team128B布局保留。能量以整数计划为准，float名义截止用于时序诊断，不会在截止时销毁背压库存。
- 完整空间链、九色调度、唯一配对、高速回退和大球粗网格均保留。不限制密集桶候选数量，因此极高局部密度仍有真实的二次碰撞成本。
- 每颗实体用实时领土面积计数判断全图是否已属己方，满足时跳过没有写入作用的染色扫描，保留大球半径刷新。计数不跨实体缓存；同子步敌方改变归属后，后续己方实体照常扣能收回。该优化不跳过粒子、墙、盾或核心碰撞，收益范围以实际同条件数据为准。
- GPU阶段计时、实际绘制FPS、完成步吞吐分别记录。异步完成延迟包含排队与帧调度，不称为阻塞同步等待；分配字节不是已测物理显存驻留。

## 需要披露的边界

当前实际规则回归已覆盖全部实体跨多个敌格每格只扣1能量，以及机枪默认10秒完整周期、均匀商余、低库存稀疏发射、超过2^53的整数输入、补弹相位/CD不重置、满池释放后重试及人工停火恢复。固定射频、真实碰撞、风暴和护盾同样采用当前规则断言；资源重开、完整长局和最终导出的实际范围以测试报告为准。没有沿用旧“普通粒子染一格耗尽”或旧时间成本断言作为通过依据，环境不能完成的项目按实际记录未完成。

普通/狙击弹丸在极端人为重叠实体里单子步最多处理72次非墙实体接触，触顶停在最后合法位置以避免零TOI死循环；真实墙段不占该预算。不能把这项保护称为无限重叠接触的完整解析。正常子步是否触顶以测试记录为准。软件设备长局或压力测试若未达到目标时间，必须记录实际时长并标为未完成；不能缩小地图、删除碰撞或套用旧版测试冒充默认配置通过。
