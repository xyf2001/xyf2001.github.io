# GPU 常驻活跃粒子索引

普通粒子和狙击保持原有 64 字节结构及稳定的物理 ID。新增的活跃 ID 表只改变访问顺序，不移动粒子状态，不改变完整邻域、九色去重、高速扫掠或整数能量结算规则。

- `binding 10`：四队武器状态，共 512 字节。
- `binding 11`：16 个 uint 头部、容量长度的活跃 ID 表、容量长度的空闲栈。普通槽和最后 8 个狙击预留槽分别管理。头部前三项分别为活跃数、普通空闲数和狙击预留空闲数；word4是死亡dirty标志。
- `binding 12`：128 字节间接调度与诊断数据。前两个三元组分别是普通粒子、普通粒子加 64 大球槽的 dispatch groups。

发射阶段只有一个 GPU invocation 从空闲栈取槽并追加活跃 ID，复杂度为 O(1)。碰撞或领土事件令能量归零时，实体立即将类型设为 0，后续碰撞检查跳过；事件结束后mode12检查GPU死亡dirty标志：有普通/狙击死亡才串行稳定压紧并回收，O(实际活跃数)；无死亡只刷新间接参数，不重写活跃表。`set_energy`将池中存活实体变为零能时atomicOr置标，压紧后清标；初始化/夹具重建清标，显式清空强制置标后回收。大球尾槽不属于该活跃表。回收不依赖CPU读回，单个死亡槽只回收一次。高死亡密度的新增dirty原子开销须用同条件实测评估。

`prepare → mode11 → move → clear grid → build grid → 九色碰撞 → events → mode12` 依次执行并插入 RenderingDevice 依赖屏障。mode11 更新发射后的间接参数，mode12按dirty决定是否压紧，并始终更新事件后的参数。运动、建桶、粒子绘制通过 `compute_list_dispatch_indirect` 使用 GPU 生成的实际活跃数量；事件、高速完整回退和低频统计也遍历活跃 ID。初始化和显式调试填充仍与最大容量有关，正常每步不再扫描整个普通粒子池。

Godot 4.6 的间接调度会将参数缓冲登记为 `RESOURCE_USAGE_INDIRECT_BUFFER_READ`；`compute_list_add_barrier` 结束并重建列表，依赖图负责计算写入到间接读取的可见性。实际测试还检查了同一子步刚出生的粒子可立即移动，避免只依赖源码推断。

设置字典中的 `gpu_profiling=true` 才启用额外候选和实际接触原子计数，正式设置默认关闭。计数覆盖已插桩的粒子对及大球接触，不包含所有墙壁反射、领土DDA采样或盾/核心几何查询；不是整个物理系统所有类型接触的总数。未开计数时的0不能解释为没有碰撞。正式遥测只额外异步读回 128 字节诊断信息。CPU 提交时间、显式阻塞读回时间和异步完成延迟分别报告；异步延迟不能当作 CPU 阻塞或单纯 GPU 执行耗时。`gpu_allocation_bytes` 是本模块申请的缓冲及输出纹理字节数，不是驱动完整显存占用。

候选/接触计数为累计 uint32，长时间运行可能回卷。基准只比较短测量窗口，差值按 `(结束值 - 开始值) & 0xffffffff` 计算；不能把未处理回卷的负差值当作实际候选数量。

`debug_readback("sample")` 提供前 64 普通槽、8 个狙击预留槽、64 大球、武器状态和池头；`all_particles` 仅供显式规则测试整表读取。`_debug_rebuild_pool_rd(count)` 是一次性基准夹具接口，正式游戏不会调用。

## 实际验证

`tests/pool_integrity_suite.gd` 在 llvmpipe 软件 Vulkan、Godot 4.6.3 下实际执行，1,744 个断言、42 个状态用例全部通过。覆盖 128、4,096、1,000,000 容量及重新创建实例，同子步运动、整数能量耗尽、重复回收/再使用、8 个预留狙击槽和异步资源释放。

最大容量 1,000,000、实际活跃 1,000 时，实际读回普通调度 16 组、运动调度 17 组，活跃 ID 为 1,000，普通空闲槽 998,992、狙击空闲槽 8。该结果验证无效容量不再扩大这些 dispatch；它不等于 FPS 提升比例，也不是 RTX 5060 Ti 的性能数据。

原始记录：`artifacts/validation-1.5/pool.log`；结构化记录：`artifacts/pool_integrity_suite.json`。

加入死亡dirty、存活pending分裂判断和空TOI候选快路后，原1,744断言/42用例再次实际通过（退出码0）。复验记录独立保存在 `artifacts/validation-1.5/pool-fastpaths.log` 与 `pool-fastpaths.json`；原记录未覆盖。此正确性复验不构成性能收益结论。
