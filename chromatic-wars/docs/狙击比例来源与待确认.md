# 狙击70%/30%比例来源与待确认事项

本轮已实现的父弹70%／子弹30%是开发期间采用的默认解释。它能进行纯整数守恒验证，但目前不能作为用户最终指定的比例对象已验收通过。

## 历史实现证据

已只读检查1.4.3冻结源码、提交`bdbad1f`和`3e263f2`、初版至1.4.3各次交付的Godot源码ZIP、原始上传ReferenceProject以及两份原始粘贴需求。未发现狙击70%/30%、双向资源分配或三级分裂的既有实现。

- 1.4.3 `shaders/battle.glsl` 第125行，`op==3` 将全部输入能量 `c.a.zw` 存入 `team[t].storm_sniper.zw`，只生成一个随机方向。
- 同文件第234行，充能完成后只调用一次 `spawn(t,2u,team[t].storm_sniper.zw,uintBitsToFloat(team[t].misc.x),...)`，然后把全部储能清零。没有第二个方向或70%/30%分配。
- 原始参考工程 `scripts/gpu_battle.gd` 第229行，`SNIPER` 使用一个随机角度、`0.09`弧度散布发射高速窄束。
- 原始参考工程 `shaders/spawn.glsl` 第27～28行，仅风暴按整圆调整角度，其他粒子在原角度附近随机散射；未实现狙击双向分配。
- 两份原始粘贴需求第62行，规定随机有效方向的窄密高速粒子束和反弹后轻微发散，没有说明70%/30%的接收对象。

以上证据只说明当前可访问历史版本没有相应实现，不能据此推断用户希望的70%/30%对象。

## 当前保留的默认实现

为保留本轮已经完成并验证过整数计算的机制，暂保留：真实实体接触完成后，子弹取得 `floor(3E/10)`，父弹保留 `E-子弹能量`，余数归父弹；双方进入下一级，第3级停止分裂。没有新增资源类型，能量总数不增加。

仍待用户确认：70%和30%分别应分配给父子弹、两个发射方向，还是其他原设定中的对象。在确认之前，测试报告必须把“当前实现的整数总量守恒”和“比例对象符合最终玩法意图”分别记录；前者实际测试可通过，后者标记待确认。
