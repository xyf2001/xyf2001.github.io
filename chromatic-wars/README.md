# 颜色大战 · 显存战场

可编辑的 Godot 桌面游戏工程：左侧每参战队4颗真实圆刚体弹药球，右侧由 Vulkan Compute 维护粒子、领土、大球、护盾和核心。正式画面直接使用主 RenderingDevice 的 `Texture2DRD`，没有整帧 GPU→CPU→GPU 绘制路径。

当前为 **1.5.4-active-cells-rescue 修改构建版，未运行游戏或测试**。九色碰撞现在只间接调度普通粒子实际占据的网格中心，保留原有邻域与配对规则；去掉无接触段的精确实体查询、非耗尽染地的TOI求根及普通速度归一化中的重复三角计算。命令上传按连续槽批量提交；没有降低分辨率、粒子数、物理子步或关闭碰撞规则。新增手动“采集GPU阶段耗时”，用于定位剩余串行瓶颈，默认关闭。

紧急保命采用独立异步事件读回与专用立即补盾提交，不再等待0.25现实秒的普通UI统计和下一次模拟flush；救援护盾保留真实能量作为防御储备，普通扩张不再花掉这笔储备。仍需GPU完成已排队的工作与CPU取球回传，不承诺零延迟或补盾后不会再次被击破。

新增1～4队开局、真实领土画笔、指定阵营/武器的单次精确整数能量输入，操作见下文。之前的整数高能粒子、每格1能量、连续有限半径染地、狙击宽度与主次尾迹、机枪微扫/10模拟秒补弹、友方碰撞开关及固定柱编辑保留。

用户提供的1.5.2实机遥测为9800X3D、RTX5080、2067活跃/10000容量、1024²领土、1536²渲染、己方碰撞关闭、4FPS、GPU批次约174ms；用户随后反馈1.5.3仍卡顿。这些不是本版同条件基准，不能计算优化比例。首接触保护仍不是后续碰撞链的全局CCD事件排序，串行领土/实体结算仍有吞吐限制。算法和风险见[本次修改说明](docs/性能与救援1.5.4.md)。

**沿用用户“修改但不测试”要求，本版只做资源导入与Windows导出构建；不启动游戏，不运行CPU/GPU规则、性能、长局或Windows内嵌PCK验证。构建状态、日志与源码/EXE哈希位于 `artifacts/build-1.5.4-no-tests/`。构建成功不等于运行通过，所有旧版记录都不能作为1.5.4通过；没有本版RTX5080或Windows实机帧率结论。**

用户后续补充将机枪目标切换CD定为0.5模拟秒：有效目标持续追踪，失效立即重选，不降低射速。历史1.4.3及原附件没有70%/30%双向狙击分配；当前1.5开发稿的父/子整数拆分暂保留，**比例的分配对象仍待确认**，不能把守恒测试解释为玩法语义已获确认，见[比例来源与待确认项](docs/狙击比例来源与待确认.md)。

## 运行与导出

推荐 **Godot 4.6.3 标准版**、Windows 10/11、支持 Vulkan 的独立或集成显卡及最新官方驱动。项目使用 Forward+。Godot 4.3 兼容分支仅对少量统计改用低频同步读回，未在4.3实测；4.6.3使用异步读回。需要可用的 RenderingDevice，失败会显示中文错误，不会回退为CPU战场。

编辑器与匹配的导出模板可从[Godot官方4.6.3发布页](https://github.com/godotengine/godot/releases/tag/4.6.3-stable)下载；本工程不需要.NET版。只运行已导出的EXE时无需安装编辑器。

1. 用 Godot 项目管理器导入 `project.godot`，等待资源导入完成。
2. 按 F6/F5 启动主场景。默认 1×、1万粒子槽、512²领土、768²渲染，粒子按自身整数能量结算。设备能及时完成计算时，1现实秒对应1模拟秒；卡顿造成积压时仍保留固定物理步，不能保证实时追上。
3. 若运行已导出的 Windows 版，解压整个构建包，再运行 `颜色大战.exe`。没有代码签名；是否能在具体机器运行仍需看显卡、驱动和系统。

手动重新导出：安装与编辑器完全同版本的官方导出模板，打开「项目 → 导出 → Windows 桌面」，选择 x86_64 并导出；或：

```sh
godot --headless --path . --export-release "Windows 桌面" export/颜色大战.exe
```

第一次导入 Compute 资源应在可用 Vulkan 的编辑器中进行，不要把无RenderingDevice的headless导入当成GPU验证。`export_presets.cfg` 已配置嵌入PCK；导出时读取标准 `RDShaderFile` 的SPIR-V，开发时可直接编译GLSL原文。

## 操作

- 空格：暂停/继续；N：暂停后单步；R：新开局；Tab：参数面板；F12：保存明确的一次性截图到 `user://`。
- 顶栏可选 0.25× / 0.5× / 1× / 2× / 4×、输入种子或生成新种子。
- 旧配置中未带倍率升级标记的0.25×首次加载迁移为1×，并保存完整合法配置和独立元数据标记；其他已选倍率保留。新版之后仍可主动选0.25×并保存，不会在每次启动被重置。
- 参数面板区分即时生效与新开局生效，提供保存、加载、恢复默认。配置保存在 `user://chromatic_wars.cfg`，不会覆盖工程。
- 「04 GPU性能与画面」中的「同阵营普通粒子碰撞」开关即时生效，点击保存可留存。关闭时己方普通粒子互相穿过；己方大球补能、大球之间碰撞及敌方结算照常。
- 所有物理坐标、半径和宽度统一为游戏单位；游戏计时统一为模拟秒，暂停时不推进。显示分辨率用像素、领土精度用格数，FPS/GPU毫秒表示真实设备表现。
- 「球详情」显示当前参战球的数值、真实物理半径、出生时锁定的门槛。
- 调试区的武器按钮是明确的人工调试发射，不属于正常对局的随机收益。
- 点击右侧「复制完整诊断与配置」可手动复制JSON：保留原诊断顶层字段，并附Godot/版本/设备、所有当前设置、归一化开局配置、GPU已提交配置、待新开局差异，以及实际固定步长、目标倍率、左侧物理和柱位。`gpu_submitted`表示主线程已提交，不能当作GPU已确认；机枪现有弹匣仍可能使用上次补弹锁定值。复制只在本机剪贴板和本地日志中记录，不自动上传、不新增网络请求或GPU读回；字体等引擎对象不写入JSON。

## 人工控制与阶段诊断

- 「01」选择参战阵营数量1～4，点击「新开局」生效；每队4颗左球，2队适合定向调试。队数可保存，当前局不被即时删除队伍。
- 「06 人工测试控制」选择参战阵营、护盾/大球/狙击/风暴/机枪，输入1～9223372036854775807的十进制整数，点击「提交一次」或在输入框按Enter。不接受负数、小数、科学计数或超限值，保留输入供修改；没有自动重复。人工输入是明确的外部能量来源，会写入本地调试日志。已淘汰阵营不能复活；GPU库存相加溢出时沿用原背压及错误处理，不静默截断。
- 暂停时也能提交武器能量，可立即入账或执行已到时发射；移动、蓄力及后续模拟计时仍需继续或单步，不额外推进模拟。
- 同区开启「人工领土画笔」会自动暂停。选择颜色/半径后收起参数，在右侧战场左键拖动，右键退出；也可显式继续模拟。画笔真实修改归属和面积统计，不花武器能量，不生成粒子或自动触发武器。半径单位独立于画面像素；左侧删柱不受影响。该能力只用于用户主动编辑，不能当作正常战斗收益。
- 卡顿时点击右侧「采集GPU阶段耗时」；下一非空模拟批次只采样首个GPU微步及最终绘制，覆盖查询/染地/九色/事件/绘制等阶段。采集会增加记录开销，完成或部分完成后点击「复制完整诊断与配置」。采样范围、缺失值、其余未采样子步与批次编号一起保留；不是长期性能测试，也不等同于纯CPU/GPU同步等待时间。

## 布局编辑与流畅预设

打开「参数设置」：

- 「布局编辑」中开启放柱模式会自动暂停，收起面板后在左侧左键放柱、右键删除预设或自定义柱；青圈为可放位置，红圈为不可放。可在出生区以下、输送带以上的空白位置编辑，不能与已有柱或倍率实体墙重叠。最多64根，可调半径，放置结果自动保存。另有恢复预设柱、清空自定义柱、清空全部柱按钮（与自定义柱重叠的预设柱暂不恢复）；删除预设柱的结果也会随配置保存，编辑不重置在场球。
- 调整×8/×4/×2通道净宽，左右镜像；三档总和超过158游戏单位会自动缩小，中央通路至少84游戏单位，底墙随通道同步调整。
- 四队大本营各有X/Y坐标，坐标使用1024×1024游戏单位的战场，修改后点击「新开局」生效。初始领土随参战队数划分，基地位置仍由各队坐标决定。
- 「护盾最大宽度」直接限制护盾最大直径，另可调整半径缩放；均在后续物理步生效。狙击弹速及蓄能时间也可调整。
- 「应用流畅预设并新开局」应用分圈风暴参数，保留当前领土精度、画面分辨率、粒子显示密度、友方碰撞开关和拖尾。参数内可调整机枪补弹后发完时长与风暴圈间隔；整圈固定360颗、最多3圈。

空间格保留分区与九色调度，同色候选默认参与碰撞，关闭开关时直接跳过己方普通粒子链；高速回退也遵循此开关。实际位移超出普通邻域覆盖的粒子进入独立链，串行完整补查。大球使用粗空间网格筛除远距离候选，吸收增长后更新索引；推动先按实际交互能量累积，再按碰前质量平滑限制整步加速度。机枪威胁在空间建桶时并行摘要，补地另有格子滚动扫描以覆盖射线之间的缺口。粒子空闲栈与活跃ID常驻GPU，移动、建桶、绘制采用间接调度；正式路径不读回活跃数来决定dispatch。性能对照必须阅读同条件原始样本，不承诺实体显卡帧率。

## 玩法与精度

默认4队基地为红左上、绿右上、蓝左下、黄右下，各25%领土；每参战队4颗数值2的弹药球，唯一护盾与机枪库存各1,000,000。可选1～4队：1队全图红色，2队红绿左右划分，3队红绿蓝近似等面积（最多相差1格），4队维持四象限。未参战队停用，不产生死亡余波或救援。

倍率由真实入口碰撞决定；完整圆进入×2/×4/×8后立即乘倍并重新发射。中央空气墙按大小、实际弹药的有界响应和有效质量施力。底部连续输送带显示和命中共用一个滚动坐标，固定窗口计数与内容计数分开。

世界门槛采用弛缓指数曲线：`100 * exp(log(10000) * (sqrt(1+t/1200)-1) / (sqrt(2)-1))`，t为模拟秒；起点100、1200模拟秒达到1,000,000，之后继续增长，相对增长率逐渐下降。目标时间和曲线时长可调。每球完整输出后锁定新出生门槛，倍率与保值防卡不更新，时间推进不直接缩小旧球。默认最大球径72游戏单位，大于默认最宽倍率口67、小于默认中央通道98。默认柱列已保证大球和侧壁间的实体净距；用户自定义布局仍需自行保留通路。左侧弹球输出的精确整数上限为2^53−1，越界保留原值并暂停；人工武器输入采用独立int64路径，上限2^63−1。浮点体积映射设1e30安全帽。

护盾、机枪、风暴、狙击、大球使用独立输出。狙击将每次输出的全部能量装入一颗高能弹，按设定速度飞行，真实半径随能量有界增长，实际参与敌方粒子抵消、领土消耗、护盾反弹和核心接触；不再使用瞬时激光，也不是连续粒子流。主弹白芯长尾、次级弹阵营色短尾不产生额外碰撞或染地。预留8个普通粒子槽给高能弹，普通粒子满载时仍有发射空间；额外高能弹可用其他空槽。容量仍不足时保留库存等待。同阵营普通粒子之间、同阵营大球之间有实体碰撞且不扣弹药；己方普通粒子命中己方大球时转移其实际能量并消失，带轻微推力。敌方粒子按实际能量削减大球，连续机枪命中会累积偏移；敌方大球相撞和撞盾按冲击强度、质量和软硬部分互耗，接触锁避免粘住时每子步连续扣除。

GPU核心统一状态为：存活→保命待定→补盾存活/确认淘汰。待定请求在CPU读取前持续锁存；CPU只抽左侧最大球并回传能量，GPU决定生死与180模拟秒CD。死亡后枪库存变风暴、四颗左球变大球余波；此前已充能狙击保留一次原定释放，不能借此复活。淘汰通知返回前已输出、到期后被拒绝的普通命令完整计入一次显式损耗，不能从能量总账消失。护盾映射参考基准与世界时间独立，充能会从核心向外真实染格，每改变一格归属支付1护盾能量。

紧急保命取消当时待执行的扩张目标与游标，将补入的真实能量标记为防御储备；直到实际承伤消耗，后续普通补盾也不能把该储备用于染地。正常补盾的非储备部分仍遵循扩张染地规则。界面按触发及GPU回传结果显示保命进度、成功或失败，并区分无球与冷却内再次被击破，不把收到一次补盾等同于此后不会死亡。本版这些新增行为尚未运行验证。

没有随时间增长的发射成本，旧成本配置也不能重新启用它。所有粒子和大球按自身真实整数能量结算；每次实际改变一个非己方格子归属只扣1能量，余能继续，己方格子不扣。1.5.2的有限半径扫掠按胶囊与格矩形严格交叠及TOI顺序结算，不靠扩大显示笔刷补色；真实轨迹覆盖不到的宽缝仍保留。敌对粒子按双方能量最小值等量抵消，幸存者沿原方向继续。狙击不被普通粒子偏转，真实墙/敌盾/敌大球接触后可发生三级70%/30%分裂；详细触发与整数余数规则见文档，比例对象仍待确认。

风暴最多3圈，每整圈360颗、完成后的圈间隔默认0.10模拟秒。输入小于360能量时只发较稀疏的一圈，不产生零能实体；充足输入选360整倍数，全部能量用整数商余分到实际粒子。容量不足保留角序与库存。机枪默认1200发/模拟秒、旋转1.7弧度/模拟秒，每发有独立子步内出生时刻。每次补弹以当时总库存E、固定射速和10模拟秒计算N个射击槽，单发为整数商`E/N`或多1，余数均匀分散，最后一槽完成整次分配；库存小于槽数时有稀疏空槽。补弹重计时而不重置射击相位、炮口或目标；正射速和时长的新参数在下次补弹锁定。射速0调试停火或物理池背压会延长实际发完时间，能量保留。

机枪目标切换CD默认0.5模拟秒，锁定期间持续跟踪；死亡、消失、能量归零或已经背离/掠过核心而无法有效攻击的目标立即失效，清除旧身份与冷却并从当前朝向继续转动。1.5.2在锁敌/补地时按每发实际模拟时刻做±2°、每模拟秒6周期的连续微扫，自由旋转不叠加微扫；无实体威胁时单个补地方向最多停留0.15模拟秒，随后连续巡转0.20模拟秒，滚动扫描游标保留。避免固定角度长串的这项修改未改变射速、整数弹匣、10秒补弹计划或射击相位，尚未运行验证。旧存档中的显式合法CD值保留，缺失或无效值才使用新默认。防守优先级只改变瞄准，不提高固定射频。

左侧机械质量与弹药能量分开，主要随自身出生门槛下的成长程度变化，绝对弹药仅作小幅有界修正；高数值球仍可移动和反弹。空气墙覆盖圆形边缘，并对未充分长大的下冲球增加连续阻力，避免尚未长大就因过重失去上托。有限推力仍可能被极端碰撞穿过，且早期出生的2048球可能已正常长大，不以当前全局门槛硬性禁止输出。防卡每0.1模拟秒采样，静止观察3、局部循环观察8模拟秒，持续确认0.4模拟秒后保值重发；重发冷却1模拟秒。保留数值、阵营、出生门槛，不触发输出、倍率或武器。正常倍率瞬移不计作运动路程；保值防卡不会禁止合法倍率循环，也不能保证消除所有超高数值攻击。

## 性能设置与限制

建议从默认精度开始，先看帧率和积压再增加容量。GPU容量选项为1万、5万、10万、30万、100万；分配前检查存储缓冲能力与预算。地图最高1024²、渲染最高1536²，以实际遥测为准。越高地图精度意味着大球每次扫掠需要处理更多格子。[性能验证](docs/性能验证1.5.md)及[物理规则发布审计](docs/物理规则发布审计.md)记录的是1.5.1及更早检查点；本次1.5.4保留专用管线、mode13并行查询及mode14单写者付款，binding13占每实体8字节加16字节摘要；binding14为每实体4字节、16KiB宽弹桶，加16384格标记/9计数/9×1849格列表（约129KiB）。binding12为64字，含9组碰撞间接命令；每队WeaponState为176字节，新增16字节防御储备；命令缓冲为1101×32字节，人工画笔使用独立尾部槽。其耗时、正确性及资源回收未运行验证，不能沿用旧版内存或性能结论。

当前为优先保证结算正确，粒子邻域碰撞使用九色空间链表，领土/护盾/大球事件使用一个GPU invocation顺序结算。**这是重大吞吐限制；没有实体显卡60FPS保证。** 固定机枪射速以有空槽为前提，物理池满时保留弹药等待，不能保证任意密度下仍无间断发射。软件Vulkan的性能数据不能外推到真实显卡；30万/100万活跃粒子的硬件压力测试尚未执行。RTX 5060 Ti的建议参数和复测步骤见[实机验收建议](docs/RTX5060Ti验收建议.md)。

固定步长与模拟时间控制CD；慢机器达到每帧步数预算时保留时间积压，界面速度是目标速度，实际模拟可能追不上。不靠跳过弹药或伤害维持表面帧率。详见测试报告中的未完成项。
