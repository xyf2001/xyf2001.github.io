# 颜色大战 · 显存战场

可编辑的 Godot 桌面游戏工程：左侧 16 颗真实圆刚体弹药球，右侧由 Vulkan Compute 维护粒子、领土、大球、护盾和核心。正式画面直接使用主 RenderingDevice 的 `Texture2DRD`，没有整帧 GPU→CPU→GPU 绘制路径。

当前为 **1.4.3-air-aim 空气墙与即时索敌版**。修复后期小球尚未长大却过重、提前冲过空气墙的原因；机枪每个有弹药的模拟子步重新索敌，取消角度保持时间；防卡缩短为静止3、局部循环8模拟秒，持续确认0.4模拟秒。参数面板新增实时「同阵营普通粒子碰撞」开关，默认开启。物理长度统一使用游戏单位，速度使用游戏单位/模拟秒，渲染像素与领土格数分别标注。保留普通粒子恒速、大球最低移速、逐圈风暴和预设固定柱编辑。**按用户要求，本轮没有运行游戏、规则测试或性能测试，仅进行源码审阅和导出打包。** 详见 `docs/空气墙与即时索敌.md`。

**请先读 `TEST_REPORT.md`。已完成的规则测试、软件 Vulkan 运行，与 Windows 实体显卡验收是不同结论。本版本不宣称全部验收清单已通过。**

## 运行与导出

推荐 **Godot 4.6.3 标准版**、Windows 10/11、支持 Vulkan 的独立或集成显卡及最新官方驱动。项目使用 Forward+。Godot 4.3 兼容分支仅对少量统计改用低频同步读回，未在4.3实测；4.6.3使用异步读回。需要可用的 RenderingDevice，失败会显示中文错误，不会回退为CPU战场。

编辑器与匹配的导出模板可从[Godot官方4.6.3发布页](https://github.com/godotengine/godot/releases/tag/4.6.3-stable)下载；本工程不需要.NET版。只运行已导出的EXE时无需安装编辑器。

1. 用 Godot 项目管理器导入 `project.godot`，等待资源导入完成。
2. 按 F6/F5 启动主场景。默认 0.25×、1万粒子槽、512²领土、768²渲染、普通粒子出生成本模式。
3. 若运行已导出的 Windows 版，解压整个构建包，再运行 `颜色大战.exe`。没有代码签名；是否能在具体机器运行仍需看显卡、驱动和系统。

手动重新导出：安装与编辑器完全同版本的官方导出模板，打开「项目 → 导出 → Windows 桌面」，选择 x86_64 并导出；或：

```sh
godot --headless --path . --export-release "Windows 桌面" export/颜色大战.exe
```

第一次导入 Compute 资源应在可用 Vulkan 的编辑器中进行，不要把无RenderingDevice的headless导入当成GPU验证。`export_presets.cfg` 已配置嵌入PCK；导出时读取标准 `RDShaderFile` 的SPIR-V，开发时可直接编译GLSL原文。

## 操作

- 空格：暂停/继续；N：暂停后单步；R：新开局；Tab：参数面板；F12：保存明确的一次性截图到 `user://`。
- 顶栏可选 0.25× / 0.5× / 1× / 2× / 4×、输入种子或生成新种子。
- 参数面板区分即时生效与新开局生效，提供保存、加载、恢复默认。配置保存在 `user://chromatic_wars.cfg`，不会覆盖工程。
- 「04 GPU性能与画面」中的「同阵营普通粒子碰撞」开关即时生效，点击保存可留存。关闭时己方普通粒子互相穿过；己方大球补能、大球之间碰撞及敌方结算照常。
- 所有物理坐标、半径和宽度统一为游戏单位；游戏计时统一为模拟秒，暂停时不推进。显示分辨率用像素、领土精度用格数，FPS/GPU毫秒表示真实设备表现。
- 「球详情」显示16球当前数值、真实物理半径、出生时锁定的门槛。
- 调试区的武器按钮是明确的人工调试发射，不属于正常对局的随机收益。

## 布局编辑与流畅预设

打开「参数设置」：

- 「布局编辑」中开启放柱模式会自动暂停，收起面板后在左侧左键放柱、右键删除预设或自定义柱；青圈为可放位置，红圈为不可放。可在出生区以下、输送带以上的空白位置编辑，不能与已有柱或倍率实体墙重叠。最多64根，可调半径，放置结果自动保存。另有恢复预设柱、清空自定义柱、清空全部柱按钮（与自定义柱重叠的预设柱暂不恢复）；删除预设柱的结果也会随配置保存，编辑不重置在场球。
- 调整×8/×4/×2通道净宽，左右镜像；三档总和超过158游戏单位会自动缩小，中央通路至少84游戏单位，底墙随通道同步调整。
- 四队大本营各有X/Y坐标，坐标使用1024×1024游戏单位的战场，修改后点击「新开局」生效。当前领土仍按四象限各25%初始化。
- 「护盾最大宽度」直接限制护盾最大直径，另可调整半径缩放；均在后续物理步生效。狙击弹速及蓄能时间也可调整。
- 「应用流畅预设并新开局」应用默认粒子成本与风暴环参数，保留当前领土精度、画面分辨率、粒子显示密度和拖尾。参数内可调整成本开始时间/增长速度、风暴每圈数量与圈间隔。

空间格保留分区与九色调度，同色候选默认参与碰撞，关闭开关时直接跳过己方普通粒子链；高速回退也遵循此开关。实际位移超出普通邻域覆盖的粒子进入独立链，串行完整补查，避免高速调试粒子漏碰撞。大球使用粗空间网格筛除远距离候选，吸收增长后更新索引；同一子步的粒子推动先按实际能量累积，再平滑限制整步加速度。机枪威胁在空间建桶时并行摘要，取消串行遍历周围粒子链的索敌。风暴分圈限制瞬间生成密度，满容量时保留库存，不跳过物理结果。本轮没有实际性能测试，不能承诺具体帧率提升。

## 玩法与精度

四阵营默认基地为红左上、绿右上、蓝左下、黄右下，开局各25%领土、4颗数值2的弹药球、唯一护盾与机枪库存各1,000,000。

倍率由真实入口碰撞决定；完整圆进入×2/×4/×8后立即乘倍并重新发射。中央空气墙按大小、实际弹药的有界响应和有效质量施力。底部连续输送带显示和命中共用一个滚动坐标，固定窗口计数与内容计数分开。

门槛默认严格为 `100 + (1_000_000 - 100) * t / 1200`（t为模拟秒，1200模拟秒后继续线性增长），每次完整输出后锁定新出生门槛；时间推进不会直接缩小已在场的球。默认最大球径72游戏单位，大于默认最宽倍率口67、小于默认中央通道98；编辑布局后以自定义净宽为准。倍率累积可能非常大，CPU命令精确整数上限为2^53−1，越界时保留原值并暂停，绝不悄悄截断。

护盾、机枪、风暴、狙击、大球使用独立输出。狙击将每次输出的全部能量装入一颗高能弹，按设定速度飞行，实际参与敌方粒子抵消、领土消耗、护盾反弹和核心接触；不再使用瞬时激光，也不是连续粒子流。预留8个普通粒子槽给高能弹，普通粒子满载时仍有发射空间；额外高能弹可用其他空槽。容量仍不足时保留库存等待。同阵营普通粒子之间、同阵营大球之间有实体碰撞且不扣弹药；己方普通粒子命中己方大球时转移其实际能量并消失，带轻微推力。敌方粒子按实际能量削减大球，连续机枪命中会累积偏移；敌方大球相撞和撞盾按冲击强度、质量和软硬部分互耗，接触锁避免粘住时每子步连续扣除。

GPU核心统一状态为：存活→保命待定→补盾存活/确认淘汰。待定请求在CPU读取前持续锁存；CPU只抽左侧最大球并回传能量，GPU决定生死与180模拟秒CD。死亡后库存变风暴、四颗左球变大球余波，不能复活。

普通粒子的整数成本为 `C(t) = 1 + floor(max(t - 60, 0) * 0.25)`（默认；可实时调整）。每次成功发射扣除完整的当前成本，并把该值锁定为粒子能量；不足一发的余数保留，不生成少付费粒子。旧粒子不会随时间加能。普通敌对粒子一对一消失，消耗各自全部出生能量；首次染到非己方领土后粒子也消失，只改变一个格子。这是新的时间经济规则，后期每格需要更多弹药，并非原版战果等价压缩。狙击仍为独立飞行聚能弹，与同阵营粒子直接穿过、与敌方粒子只抵消能量，不发生物理偏转；与大球、护盾、墙壁的交互保持原规则。大球与狙击连续逐格耗能，但每格成本使用占领时的当前普通粒子成本，不再固定扣1；不足支付一格时耗尽剩余能量且不染该格。

风暴默认每圈最多96颗、圈间隔0.10模拟秒，完整均匀分配圆周角度。少量库存可发一圈较稀疏的粒子；大量库存持续发更多圈。容量或生成预算不足时保留本圈角序继续发射，每颗均按实际发射时的成本结算。机枪默认固定1200发/模拟秒，不再随进程增长，旋转速度默认1.7弧度/模拟秒；每一发按子步内的实际发射时刻和连续炮口角度出生，不再把相邻子弹扇成短段。同色普通粒子仍真实碰撞。补地与防守平滑转向，威胁索敌和最高1.8倍临时射速保留，库存不足则等待；受阻时保留弹药，不积攒整发额度集中补发。参数内可即时调整固定射速与旋转速度。

左侧机械质量与弹药能量分开，主要随自身出生门槛下的成长程度变化，绝对弹药仅作小幅有界修正；高数值球仍可移动和反弹。空气墙覆盖圆形边缘，并对未充分长大的下冲球增加连续阻力，避免尚未长大就因过重失去上托。有限推力仍可能被极端碰撞穿过，且早期出生的2048球可能已正常长大，不以当前全局门槛硬性禁止输出。防卡每0.1模拟秒采样，静止观察3、局部循环观察8模拟秒，持续确认0.4模拟秒后保值重发；重发冷却1模拟秒。保留数值、阵营、出生门槛，不触发输出、倍率或武器。正常倍率瞬移不计作运动路程；保值防卡不会禁止合法倍率循环，也不能保证消除所有超高数值攻击。

## 性能设置与限制

建议从默认精度开始，先看帧率和积压再增加容量。GPU容量选项为1万、5万、10万、30万、100万；分配前检查存储缓冲能力与预算。地图最高1024²、渲染最高1536²，以实际遥测为准。越高地图精度意味着大球每次扫掠需要处理更多格子。

当前为优先保证结算正确，粒子邻域碰撞使用九色空间链表，领土/护盾/大球事件使用一个GPU invocation顺序结算。**这是重大吞吐限制；没有实体显卡60FPS保证。** 软件Vulkan的性能数据不能外推到真实显卡；30万/100万硬件压力测试尚未执行。

固定步长与模拟时间控制CD；慢机器达到每帧步数预算时保留时间积压，界面速度是目标速度，实际模拟可能追不上。不靠跳过弹药或伤害维持表面帧率。详见测试报告中的未完成项。

```sh
python tools/run_tests.py --godot /path/to/godot --suite settings
python tools/run_tests.py --godot /path/to/godot --suite channel_floor
python tools/run_tests.py --godot /path/to/godot --suite cpu --duration 1200 --timeout 900
python tools/run_tests.py --godot /path/to/godot --suite gpu --timeout 300
python tools/run_tests.py --godot /path/to/godot --suite stress --capacity 100000 --timeout 300
```

现存套件包含历史规则断言，尚未适配1.4的普通粒子经济与碰撞机制；本轮未执行它们。GPU套件需要普通Vulkan窗口，Linux云机可配Xvfb与Lavapipe；`--headless`不能代替它。Windows在桌面会话中运行。所有套件保留原始日志与JSON；失败、未测试和实际通过分别记录，没有断言不会报PASS。`tools/visual_smoke.gd`验证完整主场景、截图、暂停和单步。`--suite battle --capacity 64 --duration 1200 --timeout 3600`可运行明确标注的64粒子/64²地图/4096能量包双系统对局工具；全灭时记录自然结束，不能把早于20分钟的自然结束叫20分钟稳定性通过。

`tools/export_pck_smoke.gd`可在Linux以`godot --main-pack /绝对路径/颜色大战.exe --script /工程外/该脚本副本.gd -- --artifact-dir /证据目录`验证导出资源。运行目录应在工程外且不传`--path`，防止误加载开发目录。该检查实际装载内嵌SPIR-V、核验开局状态、推进Compute并采样共享纹理画面，仍不等于Windows系统启动测试。
